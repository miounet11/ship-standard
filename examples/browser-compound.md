# 例子：桌面浏览器产品如何把产品力做复利

对照 [compound](../dimensions/compound.md) 与 [probe](../dimensions/probe.md)。只写工作方式，不写对抗实现、探测站点操作或补丁细节。

---

## 他们先做对的顺序

| 阶段 | 做了什么 | 为何产品力上升 |
|------|----------|----------------|
| 看见 | 路线图、风险册、门禁、规格骨架、状态页生成器、包体基线、离线能力探针 | 第一次能不靠作者回答「现在坏在哪」 |
| 看见当天 | 第一盏 E2E 灯抓住预加载桥接静默失败；无障碍探针抓住无名表单 | 灯比感觉先发现发布级缺陷 |
| 改得动 | 渲染层拆成 api / state / view / controllers；入口变成几十行；用架构探针锁行数和分层 | 之后加功能不必改入口大文件 |
| 写成合同 | 核心能力从「装在包里的经验」变成基线分数 + 阈值；先 warn，稳定后再 block | 回退会被拦住，而不是下个版本才被人看见 |
| 骑在合同上 | 身份一致性、路径多样性、档案阶段、批量材料……每个都先有规格不变量和纯函数探针 | 新能力默认带灯，不再靠联调手感 |
| 默认不破坏 | 新闸门默认关，验证后再让团队打开 | 复利不靠一次切断旧用户 |

北极星五条（过外部门槛、行为像人、能扩并发、一个人或一个团队都能运、不能静默回退）用来否决「只因为别人有」。

---

## 七步环怎么落到日常

PR 模板强制：3 条诊断 → 规格不变量 → P0/P1/P2 → **第一笔提交是红灯** → 最小变绿 → 贴门禁证据 → 新缺口进风险册。

评审拒的是缺步，不是态度。

---

## 结构探针为什么关键

入口文件曾经一千多行、没有测试。他们没有继续在上面堆功能，而是：

- 把「入口足够瘦、view 不发 IPC、单店写入」写成不变量
- 用 E2E 架构探针锁住
- 之后里程碑才能安全加批量、生命周期、身份包

**改得动是产品力的乘数。** 改不动时，后面每个功能都在交回归税。

---

## 风险册的用法

- S1 打开 = 正式发布失败（状态页会写出来）
- 关闭的行留下，当作机构记忆
- 「目标文件自我宣称完成」本身被登记为风险：完成只认门禁

---

## 单点故障

状态汇总里任意一个加载器抛错，曾经让整个界面没数据。他们把「降级而不是炸死」写成硬化项：坏 JSON 降级、原子写、锁能释放、派生函数也有 fallback。这也是复利：表面在变大时，一个坏文件不能再毁掉整窗。

---

## 不要从这份例子里学的

- 不要把外部评分网站清单抄进自己的规格，除非那就是你的产品合同
- 不要跳过「看见 / 改得动」去抄后半段能力名
- 不要把病例长度当成架构
