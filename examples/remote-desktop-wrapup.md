# 例子：远控产品收尾（连 / 控 / 看 / 退）

对照 [diagnose](../dimensions/diagnose.md)、[quality-kernel](../dimensions/quality-kernel.md)、[acceptance-path](../dimensions/acceptance-path.md)、[pre-ship](../dimensions/pre-ship.md)。

这是一套桌面远控在「能编译、能登录」之后、公开上线之前的收尾摘要。不写账号、密钥、内网地址。

---

## 产品力怎么评

只评四柱，总分取最小值：

| 柱 | 正确率 | 效率 | 失败用户话 |
|----|--------|------|------------|
| 连 | 同身份暖机进房 | 局域网数秒内有画面 | 「一直转圈」 |
| 控 | 点哪是哪、无粘键 | 操作感知短 | 「选中一堆」 |
| 看 | 好网不锁死糊档 | 动态够帧或人话「静止」 | 「黑屏 / 幻灯片」 |
| 退 | 无残留、设备仍在线 | 再进不比首次更难 | 「退了还在控」 |

完整度不是功能多（文件、聊天、会员都有骨架），而是主路径 7 步每步可验收。

---

## 收尾时反复出现的坑

| 当时的坑 | 用了哪一条 |
|----------|------------|
| 两端显示已连接，但不能控 | diagnose：online ≠ 会话页已载入；Win 嵌入 origin 与导航 scheme 不一致 |
| 只在 Mac dev 验 Windows 行为 | diagnose：生产路径（签名包、CSP、origin）必须同版正式包 |
| 键鼠能动、画面 0 帧 | quality-kernel：媒体缓冲小于单帧 → 视频永久丢；控制通道仍活 |
| 无帧时画质档乱跳、toast 刷屏 | quality-kernel：无观测必须 hold；恢复环不得与建议环同时改分辨率 |
| 好网锁死低清晰档 | quality-kernel：空闲低帧不是弱网；自动档天花板不得被「流畅」锁死 |
| 连续小版本各打一针，商业验收从未勾完 | quality-kernel：停止消防队；一层一个 PR |
| 仓库已到较新版，用户通道还停在十几个小版本前 | quality-kernel K8：用户没装到 = 没修 |
| 虚拟机里反向控宿主：黑屏、OOM、二次确认卡死 | acceptance-path：嵌套互控是反模式，不是产品路径 |
| 一端新包一端旧包对打 | acceptance-path：双端同号再测 |
| 控制中心点了只改本地 | diagnose：产品工具必须落到对端命令 |
| 退出后粘 Ctrl、再进失败 | quality-kernel K5：退出必释放独占资源 |
| 支付 / 短信代码齐，线上未实测 | pre-ship：代码完备 ≠ 可运营；adapter 不是验收 |
| 套餐文案写限制，代码免费全开 | pre-ship：文案与权益必须一致 |
| 上架资料往前赶，主路径 7 步没勾 | pre-ship：包装服从内核 |

## 分层（本例）

```
安装同号 → 账号在线 → 壳/origin/路由 → 信令房间
  → 加密就绪 → 媒体 → 输入 → 控制中心是否真发命令
```

主路径只验：**物理机主控 → 另一端被控**。禁止在「被控跑在主控的虚拟机里」再反向控宿主。

---

## 不变量（本例锁过的）

- 无帧：自适应 hold，不 toast
- 冻屏过久：暂停软调节
- 软调节不带编码器重启、不改用户几何上限
- 媒体缓冲 ≥ 1MB 量级，且大于单帧
- 退出 / 失焦：释放全部修饰键
- 同身份有权会话：不得卡在「再点一次进入」
- 生产 API 非 localhost；各端 origin 按平台写死并单测

## 给后来者

新工作不要再堆「病例当架构」。先问四柱，再决定能不能加功能或提审。
