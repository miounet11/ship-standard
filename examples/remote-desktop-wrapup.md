# 例子：远控产品收尾（连 / 控 / 看 / 退）

对照 [diagnose](../dimensions/diagnose.md)、[quality-kernel](../dimensions/quality-kernel.md)、[acceptance-path](../dimensions/acceptance-path.md)、[pre-ship](../dimensions/pre-ship.md)。

这是一套桌面远控在「能编译、能登录」之后、公开上线之前的收尾摘要。不写账号、密钥、内网地址。

---

## 产品力怎么评

只评四柱，总分取最小值（`KERNEL-1`）：

| 柱 | 正确率 | 效率 | 失败用户话 |
|----|--------|------|------------|
| 连 | 同身份暖机进房 | 局域网数秒内有画面 | 「一直转圈」 |
| 控 | 点哪是哪、无粘键 | 操作感知短 | 「选中一堆」 |
| 看 | 好网不锁死糊档 | 动态够帧或人话「静止」 | 「黑屏 / 幻灯片」 |
| 退 | 无残留、设备仍在线 | 再进不比首次更难 | 「退了还在控」 |

完整度不是功能多，而是主路径 7 步每步可验收（`KERNEL-6` `PATH-1`）。

---

## 收尾时反复出现的坑

| 当时的坑 | 门禁 |
|----------|------|
| 两端显示已连接，但不能控；没画出分层证据 | `DIAG-1` |
| 同时改协议、UI、编码；本轮不止一个主根因 | `DIAG-2` |
| 只在 Mac dev 验 Windows 行为 | `DIAG-3` |
| 根因没写成一句话，也没补回归 | `DIAG-4` |
| 连续小版本各打一针，主柱从未用 min 评分 | `KERNEL-1` |
| 恢复环与建议环同时改分辨率 | `KERNEL-2` |
| 不变量（无帧 hold、退出释键、缓冲下限）没有测试 | `KERNEL-3` |
| 一症状一补丁式跨层大改 | `KERNEL-4` |
| 仓库已到较新版，用户通道还停在十几个小版本前 | `KERNEL-5` |
| 用功能矩阵代替尚未勾完的主路径 | `KERNEL-6` |
| 主路径 7 步没勾完仍写联调完成 | `PATH-1` |
| 虚拟机里反向控宿主：黑屏、OOM、二次确认卡死 | `PATH-2` |
| 一端新包一端旧包对打 | `PATH-3` |
| 阶段文案带协议词；设置有第二套把手 | `PATH-5` |
| 上架资料往前赶，内核门禁没过 | `PRESHIP-1` |
| 兼容矩阵与权限向导是口头的 | `PRESHIP-3` |
| 为方便关掉生产守卫 | `PRESHIP-4` |
| 法律页公网打不开，或同意版本不一致 | `PRESHIP-5` |
| 更新地址 / 公钥有两套 | `PRESHIP-6` |
| 支付 / 短信代码齐，线上未实测却对外宣称 | `PRESHIP-7` |

## 分层（本例）

```
安装同号 → 账号在线 → 壳/origin/路由 → 信令房间
  → 加密就绪 → 媒体 → 输入 → 控制中心是否真发命令
```

主路径只验：**物理机主控 → 另一端被控**。禁止在「被控跑在主控的虚拟机里」再反向控宿主（`PATH-2`）。

---

## 给后来者

新工作不要再堆「病例当架构」。先问四柱（`KERNEL-1`），再决定能不能加功能或提审。
