# 例子：长跑注册 / 收码

对照 [launch](../dimensions/launch.md) 与 [resilience](../dimensions/resilience.md)。不绑定具体站点或供应方。

| 当时的坑 | 门禁 |
|----------|------|
| 验收句不能写成测试；提交步骤没标禁止重放 | `LAUNCH-1` |
| 分类器只测自编枚举，没有真实失败原文 | `LAUNCH-2` |
| 业务失败和接口超时合成一次 retry | `LAUNCH-3` |
| 单测绿了，没有一条端到端主路径 | `LAUNCH-4` |
| 安装包或远程配置把密钥打进去；域名失败没有离线粘贴 | `LAUNCH-5` |
| 第三条路径靠在文档里公布主机地址 | `LAUNCH-11` |
| 开机说明、数据目录、STOP 路径只活在聊天里 | `LAUNCH-6` |
| 开发机跑通就拉满并发，没有一个业务周期的灰度 | `LAUNCH-7` |
| 新旧进程抢同一批资源 | `LAUNCH-8` |
| 看门狗 / 硬顶 / 降载 / 延后导入没打开 | `LAUNCH-9` |
| 回滚条件没写死；第一个小时没有成功样本 | `LAUNCH-10` |
| 供应方能力对不上申诉原因码 | `RESIL-3` |
| 别名 / 变体被当成新身份连发 | `RESIL-4` |
| 便宜类型一失败就只打最贵的一类 | `RESIL-5` |
| 导入失败把已成功的主产物回滚掉 | `RESIL-6` |
| 内存掉到阈值仍继续开窗 | `RESIL-7` |
| 日志分不清退役 / 冷却 / 降载 / 看门狗 / 延后 | `RESIL-8` |

`RESIL-1` / `RESIL-2` 已废止，分别并入 `LAUNCH-2` / `LAUNCH-1`。

写新例子时继续用这张表：左列是现场，右列是门禁 id。不要写密钥、真实账号、库存域名、主机地址。
