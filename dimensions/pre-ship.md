# 上架面：内核过了，对外材料才能算齐

品牌、商店、官网、兼容表是收尾的一部分，但**不能替代质量内核**。先看起来像成熟产品，再提审；内核柱不及格时，上架只是把问题发给更多人。

配套阅读：[quality-kernel](./quality-kernel.md) · [launch](./launch.md) 阶段 3。

---

## 一句话

**先做「看起来像成熟产品、跑起来稳、对外材料齐」；上架包装服从内核，生产守卫不许为方便而关。**

---

## 何时用

- 内测能用，准备商店 / 官网 / 安装包给第二批人
- 代码里有支付、会员、更新，但线上仍是「配置了却 501」
- 文案、图标、协议版本在桌面 / 手机 / 官网三套不一致

---

## 五条工作流（可并行，有依赖）

| ID | 工作流 | 交付 | 依赖 |
|----|--------|------|------|
| K | 内核 | 主柱过门禁 | 先于一切对外 |
| B | 品牌 | 名称、图标家族、色、slogan 锁定 | 截图和官网跟它 |
| U | 界面 | 登录 / 主列表 / 主任务 / 设置 无工程腔 | 用同一 token |
| S | 稳定与兼容 | 崩溃、重连、权限、最低系统版本 | 矩阵可勾 |
| L | 上架资料 | 商店文案、截图规范、隐私标签、法律页公网 200 | 图标先定 |

官网与下载页跟 B/L，不单独发明第三套品牌。

---

## 内测可上 ≠ 公开商用

| | 内测 / 受邀 | 公开商用 |
|--|-------------|----------|
| 登录 | 真实验证通道可用 | 协议勾选可举证；退出吊销全端 |
| 支付 | 可免费全开，但文案必须诚实 | live 下单 + 通知 + 重复通知都验过 |
| 更新 | 可手动发包 | 用户通道能吃到；协议不兼容要能拦住 |
| 合规 | 法律页能打开 | 主体、备案、隐私标签与政策一致 |
| mock | 生产 assert 禁止 | 同样禁止，且不得留调试入口 |

**代码完备度 ≠ 线上可运营。** 清单要分两列写。

---

## 生产守卫（关了就是发版失败）

- 生产包 API 必须是正式 HTTPS，拒绝 HTTP / localhost / 内网
- 生产禁止 mock 登录、占位密钥、演示用固定密钥
- 生产 CORS / CSP 只放行正式 origin
- 指标、就绪、调试口不公网裸奔
- 发版机注入的更新地址与公钥，和 API 侧清单不得漂移成两套
- `preflight` / `check:release` 绿了只证明仓库门禁；公网短信、中继、支付、更新仍要实测

---

## 品牌与文案铁律

- 用户可见名称、英文名、图标风格、强调色各只有一套
- 禁止 emoji 当主导航；禁止协议名出现在用户文案
- 套餐文案与真实权益必须一致（免费全开就写免费全开）
- 法律文档公网 200，版本号与客户端同意记录对齐
- 不为上架伪造能力截图；无盲测不写「全球第一」

---

## 验收句

1. 内核主柱未达门禁时，商店材料可以准备，但不能标「可提审」。
2. 生产配置缺少任一项守卫，安装包不得发给第二台机器。
3. 桌面 / 手机 / 官网的名称、图标、主色、协议版本能对上同一张品牌表。
4. 支付 / 短信 / 中继若在清单里存在，必须有「配置了且真实走过」的记录，不能只有 adapter。

---

## 门禁

- [ ] `PRESHIP-1` 内核门禁已过，或明确只发内测并写明限制
- [ ] `PRESHIP-2` 品牌表锁定；各端同源
- [ ] `PRESHIP-3` 兼容矩阵与权限向导写清
- [ ] `PRESHIP-4` 生产守卫未关；preflight 绿
- [ ] `PRESHIP-5` 法律页公网可开；同意版本一致
- [ ] `PRESHIP-6` 更新地址 / 公钥只有一套
- [ ] `PRESHIP-7` 支付与短信：要么实测，要么对外材料不宣称

---

## 禁止

- 用上架进度掩盖内核柱失败
- 生产开 mock / 密码登录 / localhost API
- 文案承诺的权益代码里没有闸，也不改文案
- 为视觉需求改线协议

---

## 产出

品牌表、兼容矩阵、商店/法律材料清单、生产守卫预检日志、内测 vs 商用判定。
