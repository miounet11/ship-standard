# 分层定位：一个会话只追一个根因

收尾阶段最容易浪费时间的方式：看到「连上了但不能用」，同时改协议、UI、编码、信令。正确做法是**先验证链路，再改最小代码，最后用真实路径验收**。

配套阅读：[quality-kernel](./quality-kernel.md) · [acceptance-path](./acceptance-path.md)。

产品对照见 [examples/remote-desktop-wrapup.md](../examples/remote-desktop-wrapup.md)。

---

## 一句话

**现象 → 分层定位 → 单点根因 → 最小修复 → 同版部署 → 真实路径验收 → 写回归点。**

---

## 何时用

- 功能在开发机绿了，真实双端 / 双机 / 生产包仍失败
- 多轮修补后「症状换一层再冒出来」
- 日志说成功、用户说不能用

不要和 [resilience](./resilience.md) 混用：那边管「一种失败一种动作」；这边管「先确认失败在哪一层」。

---

## 分层模型（从外到内）

上一层绿了再查下一层。每一层必须有**独立证据**（日志、截图、API、进程）。禁止用下一层失败反推上一层没问题。

```
① 安装与版本      两端同号；生产包 ≠ dev
② 账号与在线      登录成功 ≠ 会话页已载入
③ 壳 / 导航 / origin   系统回 Ok ≠ 页面真进了业务路由
④ 信令与房间      通道开了 ≠ 业务命令已允许
⑤ 加密 / 鉴权就绪  未就绪不得发业务帧
⑥ 媒体            有输入 ≠ 有画面
⑦ 输入            画面在 ≠ 点得准、无粘键
⑧ 产品工具        本地开关变了 ≠ 远端真生效
```

层数可按产品裁剪，但「上一层绿了再往下」这条不能裁。

---

## 验收句

1. 每个修复能写成一句根因，并且只落在一层。
2. `navigate` / `online` / `connected` 这类系统回执，单独不能当验收通过。
3. 修会话相关问题后，必须用**与用户相同的安装路径**再走一遍主路径，而不是只跑 `dev`。
4. 旁路问题进 backlog，不在同一提交里顺手重写邻层。

---

## 修复原则

1. **一个会话只追一个主根因。**
2. **最小 diff**：优先改壳、导航、单函数，而不是重写管线。
3. **同 version 再测。** 禁止一端新码、另一端旧包。
4. **生产路径验收。** 签名、CSP、API base、WebView origin 与 dev 不同，必须用正式包。
5. **工具输出当 stale。** 旧日志、旧统计不能直接当现状。
6. **先排除外部干扰。** 本机其它同类软件、自动化抢坐标、嵌套虚拟机会制造假失败 / 假成功。
7. **完成定义：** 真实用户路径可复现 + 可写一句根因 + 有回归点（单测或清单项）。

---

## 常见假象

| 假象 | 真实可能 | 对策 |
|------|----------|------|
| 设备 online 就能用 | 只登记成功，业务页未加载 | 查壳 / origin / 路由 |
| 系统 navigate Ok | 错误 scheme 静默失败 | origin 矩阵 + UI 可见性 |
| 一端能动另一端没画面 | 控制通道活着，媒体通道被背压打死 | 媒体与控制分开取证 |
| 键鼠不动 | 其它软件抢输入 / 未进注入路径 | 关竞品；确认注入开关 |
| 点了设置没反应 | 只改了本地 state，没发到对端 | 查是否真发出命令 |
| 很卡 | 网络或档位，不是「连不上」 | 与「完全不能用」分开提单 |

---

## 门禁

- [ ] 已画出本产品的分层，每层有独立证据
- [ ] 本轮只修一个主根因，邻层记 backlog
- [ ] 回归用同版本正式路径，不只用 dev
- [ ] 根因写成一句话，并补了单测或清单项
- [ ] 已排除外部干扰和过期日志

---

## 禁止

- 未验证链路就同时改协议、UI、编码、信令
- 只在 A 平台的 dev 里验证 B 平台行为
- 只检查系统回执，不看业务 UI 是否真出现
- 把卡顿、糊、连不上合成一张「联调失败」单

---

## 产出

分层证据、一句根因、最小 diff、同版验收记录、一条回归点。
