# 探针先行：先红，再绿，再写进门禁

产品力要复利，每一笔非平凡改动都必须留下一盏灯。灯不是作者说「测过了」，而是**先提交失败的探针，再做最小实现，证据来自门禁**。

配套阅读：[compound](./compound.md) · [quality-kernel](./quality-kernel.md) · [diagnose](./diagnose.md)。

---

## 一句话

**完成定义由范围对应的门禁说了算，不由作者说了算。先红后绿；没有探针的修复不算修复。**

---

## 何时用

- 任何非平凡改动（行为、结构、阈值、发布）
- 修 S1 / 主柱失败之后（必须带回归探针）
- 要把「经验」升级成「合同」时

平凡改动（文案错字、注释）可以不走满环，但不得借此把行为改掉。

---

## 七步环

**怎么执行七步不在本仓** —— 那是创建侧，权威是
[build-standard/practices/loop.md](https://github.com/miounet11/build-standard/blob/main/practices/loop.md)。

本纬度只管一件事：**发版材料里看得见这七步的证据**（`PROBE-1`）。怎么写 PR、怎么拆提交，看 build-standard。看不见证据就拒，不看动机。

---

## 门禁怎么从 warn 升 block

先有灯，再让灯从「评论警告」变成「阻断」。哪一级要求哪些门禁**由 `stage` 推导**，见
[gates.json](../gates.json) 的 `levels` —— 不要在这里另写一张分级表。

**warn → block** 要写升级条件，且条件必须可数：默认「连续两次 CI 全绿」。没稳定就阻断，灯会变成噪声，团队会绕过。

证据必须来自 CI 或约定的共享跑法。本机绿不算。

---

## 三种必须锁住的探针

| 种类 | 锁什么 | 例子 |
|------|--------|------|
| **行为** | 用户可见流、不变量 | 创建 → 启动 → 失败原文分类 |
| **结构** | 层、入口文件行数、禁止反向依赖 | 入口 ≤ N 行；view 不发 IPC |
| **基线** | 分数、包体、并发、崩溃 | 相对基线 ±10%；掉线则红 |

基线文件进仓库。改阈值和改代码同一 PR，并写原因。

---

## 单点故障不得炸整面

探针之外，加载路径也要复利：

- 一个坏文件 / 一个派生函数抛错，不得让整个状态 IPC 失败
- 读 JSON 损坏 → 降级，不把 UI 读死
- 写文件用临时文件再改名
- 锁表必须能收干净
- 同步派生和异步加载一样要有 fallback

「一个故障沉掉整个表面」本身就该有探针。

---

## 验收句

1. 非平凡 PR 的第一笔提交是失败的探针，随后才是最小实现。
2. 用户可见行为变了而对应 E2E / 探针没红，视为门禁缺口，记入风险册。
3. 核心能力分数相对基线回退，发布失败。
4. 本机通过、CI 没跑，不能标完成。

---

## 门禁

- [ ] `PROBE-1` PR 模板含诊断 / 规格 / 计划 / 红 / 绿 / 验证 / 反思
- [ ] `PROBE-2` 本范围的门禁列表写清 warn 还是 block
- [ ] `PROBE-3` 新行为有探针；S1 修复有回归
- [ ] `PROBE-4` 结构约定有架构探针
- [ ] `PROBE-5` 基线文件已更新或确认未回退
- [ ] `PROBE-6` 风险册在同一 PR 补了新缺口（若有）

---

## 禁止

- 「在我机器上可以」
- 「任务清单绿了」当完成
- 「测试以后再补」
- 功能 PR 里顺手重构邻文件
- 没有探针的 S1 热修
- 浅诊断上的局部补丁（见 [diagnose](./diagnose.md)）

---

## 产出

红灯提交、绿灯提交、CI 证据、更新后的规格 / 基线 / 风险行。
