# 从功能做完到真正上线

通用上线手册。不绑定某一产品、某一供应方或某一运行时。功能在开发机跑通，只算手册的起点，不算上线。

配套阅读：[长跑容错](./resilience.md)。

---

## 一句话

**开发完成 = 主路径在受控环境里绿了。真正上线 = 分类、证据、包装、灰度、观察、回滚、停机信号全部就位，并且连续跑过一个业务周期。**

---

## 阶段 0 — 承认「做完」还不是「能上」

功能开发完成时，通常只证明了：

- 作者知道怎么点
- 主路径在某一台机器、某几个账号上走过
- 测试覆盖了作者想到的情况

还没有证明：

- 真实失败原文被分类，而不是合成一种「失败」
- 密钥不在安装包里
- 对方站点、供应方接口、主机负载会拖死整场时能换路
- 能停、能回滚、能看清现场

没过下面清单，不要把安装包或配置发给第二台机器。

---

## 阶段 1 — 合同：什么叫这版可以上

1. 用现在时写验收句，每句能写成测试。「系统会更稳」不算；「资源被拒必须立刻退役并申诉，不得重提」才算。
2. 画出主路径四步：进入 → 提交 → 等待对方 → 完成。每一步标出**禁止重放**的动作。
3. 列出外部依赖：供应方、目标站、通道、导入方、许可证。每个依赖写清超时、重试、失败后主产物是否保留。
4. 列出密钥：哪些进环境/远程配置，哪些绝不能进安装包。
5. 写下停机信号：只认明确的 STOP，不认「最近全失败」。

产出：一页验收 + 一张依赖表 + 一张密钥表。

---

## 阶段 2 — 证据：用真实失败，不用想象

1. 先写红灯：分类器、比例、冷却、超时，用对方页面/接口的**原文**做测试，禁止只测自己编的枚举。
2. 至少收集 20 条真实失败现场：URL、可见正文、按钮、输入框、接口状态码（不含密钥）。
3. 业务错误和基础设施错误两套分类器，禁止混用。
4. 每条分类只映射一种动作：退款/申诉、冷却、留页等待、换通道、降并发、延后副作用。
5. CI 或至少本地全量单测 + 一条端到端主路径绿了，才进入包装。

产出：测试日志、失败原文样本、分类表。

---

## 阶段 3 — 包装：别人装上就能跑

1. 版本号能区分上一包（不要 silently 覆盖同名「最新」却说不清差在哪）。
2. 安装包不含密钥、不含调试转储、不含上一轮脏库存。
3. 配置可从 URL 加载，也可整段粘贴；机器访问不了域名时要有 IP 或离线粘贴。
4. 第一次启动清单写进面板或一页纸：装内核 / 填配置 / 点启动 / 数据落在哪 / 怎么停。
5. 未签名包要写明系统会拦，以及操作者该怎么放行。
6. 下载目录关闭列表；带密钥的配置 URL 当密码保管。

产出：安装包、配置模板、一页开机说明。

---

## 阶段 4 — 灰度：先小并发，再拉满

不要用「开发机跑通」代替灰度。

1. **最小火力**：1–4 路并发，只跑一个完整业务周期（获取资源、提交、等待、完成、导入）。
2. **看日志能否分清**：退役、冷却、类型暂停、启动失败、主机降载、看门狗、导入延后。分不清就回去补日志，不要加并发。
3. **对一下比例**：该交错的资源有没有变成只打最贵的一类。
4. **对一下频控**：有没有把「请 N 分钟后再试」当成「对方不认」然后连点提交。
5. **对一下主机**：内存掉到阈值时有没有降窗口，而不是继续开。
6. 灰度通过后再把并发收到设计上限，并打开看门狗。

产出：灰度记录（时间、并发、成功/退役/冷却、是否出现空转）。

---

## 阶段 5 — 上线：切过去，但留退路

1. 旧进程先 STOP，再切新包，避免两套逻辑抢同一批资源。
2. 新包自带：硬顶时间、线程崩溃兜底、无进展升级、余额不足退避、冷却中仍允许新获取。
3. 回滚条件预先写死：例如「连续 N 分钟零进展且看门狗已 unstick 仍零进展」或「错误消耗资源的速度超过完成速度」。触发则停新包、恢复上一包，而不是继续加补丁空转。
4. 上线公告只发：安装地址、配置地址、怎么停。不发密钥明文到群。

产出：上线记录、回滚开关位置、STOP 路径。

---

## 阶段 6 — 上线后第一个小时 / 第一天

**第一个小时**

- 主路径至少成功一次
- 每一种已知失败至少出现一次时，动作与分类表一致
- 没有「同一资源死循环」
- 导入失败没有把已成功的主产物回滚掉

**第一天**

- 并发按设计上限跑过一个完整工作时段
- 主机降载发生过或明确没有触顶
- 申诉/退款对得上原因码
- 看门狗若触发，事后能说清它做了什么

任一小时级检查失败：降并发或回滚，不要「再观察一晚」。

---

## 阶段 7 — 日常运转

- 停机只走 STOP 或面板停止，等在途尝试结束；超时再杀进程
- 密钥轮换：配置 URL 当密码；泄露即作废重发
- 拉黑名单、跳过名单、延后导入队列要可持久化，重启不丢
- 每周把新的失败原文补进分类测试，分类器过期比代码过期更快

---

## 阶段 8 — 容错内核（必须写进产品，不能只写进聊天）

1. **先取证，再归类。** 禁止凭印象定性。
2. **一种问题一种动作。** 禁止用重提治疗频控，禁止用整类停买治疗坏资源，禁止用禁止新获取治疗脏池。
3. **提交动作精确。** 按钮用整段文案相等。
4. **资源身份归一。** 变体在目标站可能是同一账户。
5. **等待看对方做到哪一步。** 已寄出就留页加长等；频控就冷却并捞旧信。
6. **业务故障和基础设施分开。** 接口/运行时/CPU 走退避和降并发。
7. **任何一层都不能卡死整场。** 停机只认 STOP。

细节见 [resilience.md](./resilience.md)。

## 上线门禁（打印用）

功能开发完成后，下列全部勾上才算真正上线：

- [ ] `LAUNCH-1` 验收句可测试，主路径四步标了禁止重放
- [ ] `LAUNCH-2` ≥20 条真实失败原文进了分类测试
- [ ] `LAUNCH-3` 业务分类与基础设施分类分开，每类一种动作
- [ ] `LAUNCH-4` 单测绿，主路径至少一条端到端绿
- [ ] `LAUNCH-5` 安装包无密钥；配置可 URL / 粘贴 / IP
- [ ] `LAUNCH-6` 开机说明、数据目录、STOP 路径写清
- [ ] `LAUNCH-7` 小并发灰度过了一个业务周期，无空转
- [ ] `LAUNCH-8` 旧进程已停，新旧不抢同一资源
- [ ] `LAUNCH-9` 看门狗、硬顶时间、降载、延后导入已打开
- [ ] `LAUNCH-10` 回滚条件写死，第一个小时的成功样本已看到

没勾完的那一项，就是还不能上线的原因。
