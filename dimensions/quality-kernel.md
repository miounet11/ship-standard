# 质量内核：先锁不变量，再扩功能

收尾时最常见的假进度：每个版本修一个联调症状，文档写「已修」，用户却吃不到，下一症状从另一层冒出。这不是迭代，是消防队。

产品力不是功能清单长度，而是用户完成主任务的**正确率 × 效率 × 完整度**。

配套阅读：[diagnose](./diagnose.md) · [acceptance-path](./acceptance-path.md) · [launch](./launch.md)。

---

## 一句话

**先锁内核不变量，再扩功能。任何一柱失败，总分就是失败。用户没装到的修复 = 没修。**

---

## 何时用

- 连续几个版本都在打补丁，商业验收从未勾完
- 同一条链路上有多套状态机同时改核心参数
- 仓库版本已经往前走，线上 / OTA / 用户包还停在旧版
- 想用新功能（支付、企业、AI）掩盖主路径不稳

---

## 产品力只评主柱

按产品写 3–5 根柱。远控类常用 **连 / 控 / 看 / 退**；其它产品换成自己的主任务柱。评分用 **最小值，不用平均分**。

```
        柱 A                    柱 B
     必须先做成              必须同时做成
              \                /
               产品力 P = min
              /                \
        柱 C                    柱 D
```

| 规则 | 含义 |
|------|------|
| **P = min(各柱)** | 禁止用「文件传输做了」补「画面糊」 |
| 每柱同时量正确率与效率 | 「能连」但 30 秒转圈，连柱仍失败 |
| 完整度看主路径 | 不看功能矩阵打勾数量 |
| 无盲测不得写超越竞品 | 内部感觉不是证据 |

---

## 每层只做一件事

收尾补丁变多，通常是因为**多层同时拥有改同一参数的权力**。

| 层 | 只做 | 禁止 |
|----|------|------|
| 用户意图 | 写天花板 | 直接改拥塞旋钮 |
| 观测 / 建议 | 报网情、报健康 | 无数据时升降档 |
| 执行端 | 在天花板内调速率 | 把用户上限永久改小 |
| 恢复 | 只救通路 | 与建议环同时改几何 / 分辨率 / 身份 |
| 会话状态机 | 唯一对外文案 | 多处 reload、多套「连接中」 |
| 控制通道 | 优先、不可丢 | 被媒体通道堵死 |
| 媒体通道 | 可丢、尽力传 | 缓冲阈值小于单帧 |
| UI | 人话 + 单一入口 | 工程词、第二套常驻设置 |

把「谁可以改什么」写成表。两套环同时改同一旋钮 = 发版失败。

---

## 不变量（破坏 = 发版失败）

不变量必须进测试。下面是跨产品可复用的一组；产品自己的病例补进 `examples/`。

| ID | 不变量 |
|----|--------|
| K1 | 无有效观测时，自适应 **hold**，不提示、不跳档 |
| K2 | 恢复路径不改用户上限，不 hard restart 核心管线 |
| K3 | 媒体缓冲地板 ≥ 最大单帧的数倍；控制通道单独配额 |
| K4 | 空闲（低活动 + 干净网）不得当成弱网降级 |
| K5 | 退出 / 失焦必须释放独占资源（键、锁、句柄、会话） |
| K6 | 有权的自动路径不得卡在「请再点一次进入」 |
| K7 | 生产 API / 密钥 / mock 与 dev 隔离；生产包拒 localhost |
| K8 | 发版：相关端 **同号**；用户通道版本不得落后仓库超过一个次版本 |
| K9 | 用户可见文案无协议 / 算法 / 内部状态机名字 |
| K10 | 一层一个 PR；禁止同一提交同时改建议环、恢复环、通道、进房 |

---

## 工程方法（替代消防）

1. **先写不变量测试，再改环。**
2. **一层一个 PR。**
3. **联调只验证柱，不发明新环。** 只答：连不连、控不控、看不看、退不退。
4. **用户没装到的修复 = 没修。** 分发 / OTA 滞后超过一个次版本 = 质量事故。
5. **完整度用主路径，不用功能矩阵。**
6. **病例文档不是架构。** `BUGFIX_*` 只留历史，新工作不要再堆病例当设计。

---

## 验收句

1. 发版说明按主柱写变更，不按「修了某个 HUD 文案」写。
2. 仓库 version 与用户能装到的 version 差 ≤ 一个次版本。
3. 无观测数据时，档位 / 提示 / 恢复环都不得动作。
4. 结束会话后，独占资源被释放，再进不带上次状态。

---

## 门禁

- [ ] `KERNEL-1` 本产品的主柱已写下，评分用 min 不是平均
- [ ] `KERNEL-2` 每层唯一职责表已写，无两环同改一旋钮
- [ ] `KERNEL-3` K1–K10 或等价不变量有测试
- [ ] `KERNEL-4` 本轮没有「一症状一补丁」式跨层大改
- [ ] `KERNEL-5` 用户通道已能吃到本版（OTA / 安装包 / 商店）
- [ ] `KERNEL-6` 主路径清单仍是尚未勾完的那份，没有用功能矩阵代替

---

## 禁止

- 联调看到异常就在三四个模块各打一针然后 +0.01
- 文档写「已修」但用户通道还停在旧包
- 为上架或对标竞品堆功能，内核柱仍低于及格
- 无证据写「已超越」

---

## 产出

主柱评分、不变量测试、单权威表、与用户通道对齐的版本号。
